# SEO Phase 2 + Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship JSON-LD structured data for every entity type (Article / Person / Organization / WebSite / BreadcrumbList) plus AEO polish (visible breadcrumbs, meaningful image alt, author bio card on article pages, related articles, llms.txt, splash JS-injection) — so AI answer engines can cite Wild Media accurately and Google can render rich results.

**Architecture:** Add a single `src/lib/schema.ts` with pure JSON-LD builder functions (fully unit-testable), a single `<JsonLd>` component that stringifies+emits them, and per-page schema wiring via the `<slot name="head">` that Phase 1 opened in `Base.astro:80`. AEO surface work reuses the same `Crumb[]` helper for both JSON-LD BreadcrumbList and the visible `Breadcrumbs.astro` UI so the two never drift. All output stays fully static (SSG).

**Tech Stack:** Astro 5 (SSG, `output: 'static'`), Schema.org JSON-LD via inline `<script type="application/ld+json">`, Vitest for pure-function unit tests, Supabase Postgres (read-only at build), TypeScript.

## Global Constraints

- Language: Japanese for user-facing copy (`<html lang="ja">` at `src/layouts/Base.astro:65`). Schema.org values that are text (`headline`, `name`, `description`, `alt`) stay in the article's language — do not translate.
- Rendering: SSG only (`output: 'static'` at `astro.config.mjs:11`). No SSR, no client-side JSON-LD generation. JSON-LD must be present in the raw HTML that ships from `dist/`.
- Trust boundary: Permissions and business rules stay in DB layer (RLS / triggers / pgTAP). No DB writes in this plan — schema.ts + integrations are read-only.
- Draft filter: all reads must inherit `.eq('status','published').eq('moderation_hold', false)` — `fetchRelatedArticles` (Task 8) and the `llms.txt` generator (Task 9) both MUST filter drafts out.
- Never place service role key in `admin/`. `src/lib/supabase-server.ts` only, at build time.
- URLs in JSON-LD: use absolute URLs built from `Astro.site` via the existing `absoluteUrl()` helper at `src/lib/seo.ts:8`. Never emit relative URLs in schema.
- Dates in JSON-LD: ISO 8601 via the existing `toIsoDate()` at `src/lib/seo.ts:1`. `ArticleSummary` already carries `publishedAtISO` / `updatedAtISO` from Phase 1.
- Test conventions: Vitest for pure functions in `tests/*.test.ts` (run via `npm test`). Astro layouts / markup verified by `npm run build` + inspecting `dist/`. No pgTAP needed in this plan (no schema changes).
- Docs discipline: `CLAUDE.md` / `ARCHITECTURE.md` / `docs/DATABASE.md` / `docs/DOMAIN-CHANGE.md` — no structural changes here that require doc updates; but if the llms.txt generator (Task 9) becomes a permanent build step, mention it in `README.md`'s command list.
- Publisher identity: use `Wild Media` as the fixed publisher `Organization` name across all schemas, `Astro.site` as its URL. No logo URL for now (omit rather than fake).

- [ ] **Step 3: Implement `src/lib/schema.ts`**

Create the file with pure builder functions matching the tests above. Requirements:
- All builders return plain objects with `@context: 'https://schema.org'` at top level.
- Optional fields are OMITTED (not set to `null`/`undefined`) when absent — schema validators reject `"image": null`.
- `articleSchema.dateModified` falls back to `datePublished` when `updatedISO` is null.
- `breadcrumbListSchema` builds full absolute URLs by joining each crumb's `url` with `siteUrl` (use `new URL(url, siteUrl).href`).
- `Crumb` type: `{ name: string; url: string }` — `url` is a site-relative path (leading `/`).
- Export `buildCrumbs` as a plain object with methods (`.article`, `.writer`, `.provider`, `.area`).

```typescript
// src/lib/schema.ts (skeleton — implement per tests above)
export interface Crumb {
  name: string;
  url: string;
}

interface ArticleSchemaInput {
  title: string;
  description: string;
  url: string;
  coverUrl: string | null;
  publishedISO: string;
  updatedISO: string | null;
  authorName: string;
  authorUrl: string;
  siteName: string;
  siteUrl: string;
}

export function articleSchema(input: ArticleSchemaInput): Record<string, unknown> {
  const s: Record<string, unknown> = {
    '@context': 'https://schema.org',
    '@type': 'Article',
    headline: input.title,
    description: input.description,
    datePublished: input.publishedISO,
    dateModified: input.updatedISO ?? input.publishedISO,
    inLanguage: 'ja',
    author: { '@type': 'Person', name: input.authorName, url: input.authorUrl },
    publisher: { '@type': 'Organization', name: input.siteName, url: input.siteUrl },
    mainEntityOfPage: input.url,
  };
  if (input.coverUrl) s.image = input.coverUrl;
  return s;
}

// ... (personSchema, organizationSchema, webSiteSchema, breadcrumbListSchema, buildCrumbs)
```

Implement the remaining builders following the same pattern. `buildCrumbs` uses `/writers/${slug}`-style paths — no absolute URLs (that's `breadcrumbListSchema`'s job).

**Files:**

- Modify: `src/pages/articles/[slug].astro`

**Interfaces:**
- Consumes: existing `ARTICLE_SELECT` and `toSummary`.
- Produces:
  - `fetchRelatedArticles(db: SupabaseClient, article: ArticleSummary, opts?: { limit?: number }): Promise<ArticleSummary[]>` — returns up to `limit` (default 6) articles, prioritized by: (1) same author AND same region, (2) same author, (3) same region, (4) most recent. Excludes the source article itself. Never returns drafts/held.
  - `<RelatedArticles articles={...} />` — renders card grid mirroring the writer-page card style.

- [ ] **Step 1: Add `fetchRelatedArticles` to `src/lib/content.ts`**

At the bottom of `src/lib/content.ts`, add:

```typescript
// 「関連記事」— 同じ著者 かつ 同じ region を最優先、次に著者一致、次に region 一致、
// 最後に最新記事。draft/held は常に除外。ソース記事自体も除外。呼び出し側は Article
// ページからのみ想定(記事詳細を1本立ち上げるコストは既に払っているため)。
export async function fetchRelatedArticles(
  db: SupabaseClient,
  article: ArticleSummary,
  opts: { limit?: number } = {},
): Promise<ArticleSummary[]> {
  const limit = opts.limit ?? 6;
  // 素直に candidates を広めに取ってきてからJS側で優先度スコアで並べ替える。
  // article数がスケールしても、上限は「同一region + 同一著者 + 新着」の和なので過大にはならない。
  const { data, error } = await db
    .from('articles')
    .select(ARTICLE_SELECT)
    .eq('status', 'published')
    .eq('moderation_hold', false)
    .neq('id', article.id)
    .order('published_at', { ascending: false })
    .limit(60); // 60本まで見れば十分な候補プール
  if (error) throw error;

  const candidates = (data ?? []).map(toSummary);
  const score = (c: ArticleSummary) => {
    let s = 0;
    if (c.authorSlug === article.authorSlug) s += 2;
    if (c.region && c.region === article.region) s += 1;
    return s;
  };
  return candidates
    .map((c) => ({ c, s: score(c) }))
    .sort((a, b) => b.s - a.s || (a.c.publishedAt < b.c.publishedAt ? 1 : -1))
    .slice(0, limit)
    .map(({ c }) => c);
}
```

- [ ] **Step 1: Create the integration**

`src/integrations/llms-txt.ts`:

```typescript
import type { AstroIntegration } from 'astro';
import { promises as fs } from 'node:fs';
import path from 'node:path';

export function llmsTxt(): AstroIntegration {
  return {
    name: 'llms-txt',
    hooks: {
      'astro:build:done': async ({ dir, logger }) => {
        // Lazy-import to avoid loading Supabase during dev.
        const { supabaseServer } = await import('../lib/supabase-server');
        const { fetchPublishedArticles } = await import('../lib/content');

        const site = process.env.PUBLIC_SITE_URL ?? 'https://wyld-media.vercel.app';
        const { featured, normal } = await fetchPublishedArticles(supabaseServer);
        const all = [...featured, ...normal];

        const lines: string[] = [];
        lines.push('# Wild Media');
        lines.push('');
        lines.push('> 環境と生き方を書く、日本のライターによるメディア。森・山・海・街から、書き手それぞれの視点で綴る記事を毎週公開。');
        lines.push('');
        lines.push('## Articles');
        lines.push('');
        for (const a of all) {
          const url = new URL(`/articles/${a.slug}`, site).href;
          const desc = a.description.replace(/\s+/g, ' ').trim();
          lines.push(`- [${a.title}](${url})${desc ? `: ${desc}` : ''}`);
        }
        lines.push('');

        const outPath = path.join(dir.pathname, 'llms.txt');
        await fs.writeFile(outPath, lines.join('\n'), 'utf8');
        logger.info(`wrote ${all.length} articles to llms.txt`);
      },
    },
  };
}
```

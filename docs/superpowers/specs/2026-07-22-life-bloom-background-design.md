# トップページ背景「対称ライフゲーム(開花)」 設計

2026-07-22

## 目的

トップページ背景の等高線アニメーション(`src/scripts/contours.ts` / `src/components/organisms/BgContours.astro`)を、
コンウェイのライフゲームをベースにした、植物・花をモチーフにした対称パターンに置き換える。
既存の「静かで知的な質感・コンテンツの邪魔をしない」という役割は維持する。

## 決定事項

### シミュレーションと描画を分離する

CPU 側の軽量な TypeScript シミュレーション(本物のライフゲームのルール)が世代を進め、
その盤面を `THREE.DataTexture` として GPU に渡し、フラグメントシェーダで拡大・色付け・
ぼかしを行う。既存の three.js シーン構成(レンダラ・RAFループ・resize/visibility/
reduced-motion 制御・WebGL非対応時のフォールバック)はそのまま流用する。

代替案として検討したが採用しなかったもの:

- **GPU側だけで完結するping-pongライフゲーム**(2枚のfloatレンダーターゲットを交互に
  使い、近傍カウントもシェーダ内で行う方式): 対称性を保証するために境界での鏡映
  サンプリングが必要になり複雑。セルの「経齢(色付けに使う)」を保持するには追加の
  レンダーターゲットが要る。盤面が安定/振動したかの判定(再播種のトリガー)も結局
  CPU側での読み出しが必要になり、GPU完結のメリットが薄れる。
- **本物のライフゲームのルールを使わず、手付けで「開花」に見えるアニメーションを作る**:
  見た目の調整はしやすいが、「ライフゲームを使う」という要求に反するため不採用。

### 対称性は「D4対称な初期盤面」だけで保証する

ライフゲームの近傍ルール(ムーア近傍・等方的)は、正方形格子自身が持つ対称群
(90°回転4種+鏡映4種、位数8のD4)と可換。つまり **初期盤面がD4対称であれば、
以降の世代も自動的にD4対称であり続ける**。座標の折り返し(fold)やミラーサンプリング
は一切不要——盤面の1/8ウェッジだけをランダムに播種し、残り7領域へコピーするだけでよい。

これにより「万華鏡のような放射対称」という要求を、追加の複雑さなしに満たせる。

### 盤面仕様

- グリッドサイズ: 128×128(固定、D4の中心が格子の中心に来るよう偶数×偶数)
- 境界: 有界(死んだセルの縁)。トーラス(ラップアラウンド)にはしない —
  境界なしだと中心から外側へ広がっていく「開花」感が出るため。
- 世代の進行間隔: 約150ms(毎秒6〜7世代)。描画のRAFループ(既存の30fps制限)とは
  独立させ、成長が一段ずつ見えるペースにする。
- セルの経齢(age): 生存世代数をセルごとに保持し、色付けに使う。
- 死亡セルの残光: 即座に消さず、数百ms程度フェードアウトする値を保持する
  (色付けのグラデーションに使う)。

### 再播種(reseed)のルール

以下のいずれかの条件で、中心付近に新しい小さな対称シード(D4の1/8ウェッジに播種→
ミラー)を**既存の盤面に重ねて**追加する(全消去はしない):

1. 盤面が安定/振動している判定: 直近数世代の盤面のローリングハッシュが一致する
   (静物・振動子の両方をカバー)
2. 人口(生存セル数)が閾値を下回った
3. 上記に関わらず、約40秒ごとのタイマー

これにより、画面が完全に真っ暗になったり固まったりすることなく、繰り返し「開花」が
起きているように見える。

### カーソルとの連動はなし

旧版にあったカーソル追従の隆起効果は踏襲しない。静かな背景要素として自律的に
動くのみとする(将来的にカーソル付近のセルを生存させる等の演出を足すことは可能だが、
今回のスコープには含めない)。

### 配色

`src/styles/global.css` の紙・墨をベースにしたパレット(`--color-bg: #ece4d2` /
`--color-ink: #35301f` / `--color-meta: #8d8168`)に馴染む、彩度を抑えた植物色を使う。
旧版の「サイケデリックな緑」路線からは離れ、経齢に応じて色相を変える:

- 誕生直後: 淡い若葉色(スプラウトグリーン)
- 定着後: 深い葉色(旧contoursの緑系を踏襲した落ち着いた緑)
- 経齢のピーク(死の直前): 抑えたローズ/テラコッタ(「花びら」のアクセント)
- 死亡中: `--color-meta` 方向へフェードしながら透明化

不透明度レンジは旧contoursと同じ0.28〜0.42を維持し、「背景として静かに存在する」
という役割を崩さない。

### 描画のぼかし・にじみ

セルをそのまま矩形として描画すると格子状のドットに見えてしまうため、フラグメント
シェーダ側で軽くぼかし・にじみを加え、セルが融合して「花」や「群落」のように
見えるようにする(旧contoursの、輪郭がにじんだ質感を踏襲)。

## 影響範囲

- 置き換え: `src/scripts/contours.ts` の中身(WebGL判定・ホスト取得・resize/
  visibility/reduced-motion制御はほぼそのまま、フラグメントシェーダとRAFループ内の
  更新ロジックのみ差し替え)
- 新規: 盤面シミュレーションを担う小さなモジュール(1ファイル。`src/scripts/`配下)
- `BgContours.astro` はマウント先の `#bg-contours` を変えないため無改修、または
  コメント文言のみ更新
- 呼び出し元(`src/pages/[...page].astro`)は無改修

## テスト・検証方針

- ロジック層(盤面の世代更新・D4ミラーリング・安定判定・再播種条件)は関数として
  切り出し、`npm test`(Vitest)でユニットテスト可能にする
  (例: 既知のライフゲームパターン(グライダー等)を1/8ウェッジに播種し、
  数世代後の盤面がD4対称であることを検証する)
- 描画(シェーダ・色付け)は目視確認。`npm run dev` で `/`(トップページ)を開き、
  以下を確認する:
  - 中心から対称に成長していく
  - 安定/振動時に新しい開花が始まる
  - reduced-motionで静止画になる(またはコンポーネント自体が描画されない)
  - WebGL非対応環境で何も描画されない(エラーにならない)

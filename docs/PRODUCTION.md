# 本番の仕組み

## 全体像

本番は 3 つの外部サービスで動いてる。1 台のサーバじゃない。

```
        ┌──────────────────┐
        │    Vercel        │  ← サイトを配信
        │  (公開 + CMS)    │
        └────────┬─────────┘
                 │
                 ↓
        ┌──────────────────┐
        │    Supabase      │  ← データを保存
        │  (DB + ログイン) │
        └────────┬─────────┘
                 │
                 ↓
        ┌──────────────────┐
        │  Cloudflare R2   │  ← 画像を保管
        └──────────────────┘
```

## 誰が何をするか

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   Vercel    │  │  Supabase   │  │     R2      │
├─────────────┤  ├─────────────┤  ├─────────────┤
│  📄 記事を   │  │  📚 記事の  │  │  🖼️  画像   │
│    表示     │  │    中身     │  │    ファイル │
│             │  │             │  │             │
│  ✏️ 編集画面 │  │  👤 ログイン│  │             │
│    (CMS)   │  │    /招待    │  │             │
└─────────────┘  └─────────────┘  └─────────────┘
```

## 手元 vs 本番

**同じ設計図で動く別々の実物**。

```
             📁 git リポ (このフォルダ)
             ┌────────────────────────┐
             │  設計図(migrations,   │
             │  アプリのコード)       │
             └───────────┬────────────┘
                         │ 同じ設計図
              ┌──────────┴──────────┐
              ↓                     ↓
       ┌────────────┐        ┌────────────┐
       │  手元      │        │   本番     │
       │ (Docker)  │        │(supabase.  │
       │            │        │   com)    │
       │ 開発・テスト│        │ ユーザー用 │
       └────────────┘        └────────────┘
```

- 手元をいじっても本番は変わらない
- 本番に反映するには「push」する

## 記事を公開したときに起きること

```
    ライターが CMS で「公開」ボタン
              │
              ↓
    ┌────────────────────┐
    │  Supabase の DB    │
    │  articles を更新   │
    └─────────┬──────────┘
              │
              ↓ (自動)
    ┌────────────────────┐
    │  Vercel が         │
    │  サイトを再ビルド   │
    └─────────┬──────────┘
              │
              ↓ 数分後
    ┌────────────────────┐
    │  読者に見える 🎉   │
    └────────────────────┘
```

ライター・プロバイダーのプロフィール更新でも同じ再ビルドが走る(admin のプロフィールと下書きの保存では走らない)。同時に何件更新されても、Vercel が古いビルドを自動キャンセルして最後の1つに畳むので無駄なビルドは残らない。詳細な配線は [superpowers/DEPLOYMENT-CHECKLIST.md](superpowers/DEPLOYMENT-CHECKLIST.md) を参照。

## コードを更新したいとき

```
    エディタで直す
        │
        ↓
    git push
        │
        ↓ (自動)
    Vercel が
    デプロイし直す
        │
        ↓ 数分後
    本番に反映 🎉
```

## DB のスキーマを変えたいとき

```
    supabase/migrations/ に .sql を追加
              │
              ↓
    supabase db push
              │
              ↓
    本番 DB に反映 🎉
```

## 設定・機密の置き場

```
┌──────────────────────────────────┐
│ PRODUCTION-SECRETS.local.md      │  ← パスワード、API キー全部
│ (リポルート、git 追跡外)          │
└──────────────────────────────────┘

┌──────────────────────────────────┐
│ Vercel Dashboard                 │  ← アプリの環境変数
│ (Settings → Env Variables)      │
└──────────────────────────────────┘

┌──────────────────────────────────┐
│ Supabase Dashboard               │  ← Auth 設定(招待の URL等)
└──────────────────────────────────┘
```
